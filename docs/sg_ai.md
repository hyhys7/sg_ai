# 먼저, 생각 (Think First)

AI에게 묻기 전에, 스스로 생각을 정리하도록 유도하는 스킬

---

## 이 프로젝트가 뭔가요

사람들이 무언가 궁금할 때 바로 AI에게 묻는 것이 습관이 되면서, 스스로 생각해보는 힘과 의지가 점점 줄어드는 현상을 막고 싶어서 만드는 스킬입니다. AI는 곧바로 답을 주지 않고, 사용자가 짧고 성의 없이 넘긴 말이라도 되물으며 상황과 생각을 스스로 구체화하도록 유도합니다. 충분히 대화가 쌓인 뒤에야 AI가 답을 주고, 그 답을 사용자 자신의 생각과 나란히 보여줘서 스스로 비교해보게 합니다.

> **방향 전환 (멘토 피드백 반영, 2026-08-08)**: 처음엔 독립 웹서비스(Next.js/Vercel)로 기획했으나, 이미 Claude/GPT에 유사한 되묻기 접근이 존재하고(안드레이 카파시가 공개한 방식과도 유사) 새 프로덕트를 만드는 것보다 기존 AI 위에 "스킬"을 얹는 방식이 유용성이 더 크다는 지적을 받아 피벗했다. 실제 구현은 `sg_ai/.claude/skills/think-first/SKILL.md` (v0.1)에 있다. 이 문서는 컨셉/기획 기록으로 유지한다.

## 핵심 사용자 플로우

1. 사용자가 Claude 대화에서 이 스킬을 명시적으로 부른다 (예: "먼저 생각 모드로 해줘")
2. 사용자가 아무 말이나 입력한다 (예: "피곤해")
3. AI는 답을 주지 않고, 상황을 구체화하는 질문을 딱 1개만 되묻는다 (예: "무엇 때문에 피곤한가요?")
4. 사용자가 답하면, AI가 다시 되묻는다. 이 과정을 반복한다
5. 사용자 턴이 3회 이상 쌓이면 "답을 받아볼지, 더 이야기할지" 물어본다 (강제 아님)
6. 사용자가 "답변 받아보기"라고 말하면, 지금까지의 대화 전체를 맥락으로 AI가 최종 답변을 생성한다
7. "내 생각(대화 전체 요약)"과 "AI 답변"을 순서대로 구분해서 보여준다
8. 별도 로그인/저장 없음. 대화가 곧 상태이므로 새 대화를 시작하면 초기화됨

## MVP 범위 (v0.1)

**포함**
- 스킬 트리거 조건 (사용자가 명시적으로 부를 때만 동작)
- AI 되묻기 로직 (조언/정답 금지, 질문 1개만)
- 사용자 턴 카운트 및 3턴 이상 시 답변 여부 확인
- 최종 답변 생성 (전체 대화 맥락 반영)
- 내 생각 vs AI 답변 비교 포맷
- 5턴 이상 반복 시 되묻기 중단 (무한 반복 방지)

**제외 (추후 검토)**
- 과거 기록 저장/조회 (다이어리, 저널)
- AI의 평가/점수 기능
- 여러 대화를 모아 패턴 분석해주는 기능
- 독립 웹서비스/모바일 설치형 앱 (스킬로 충분히 검증된 뒤 재검토)

## 구현

- **형태**: Claude Code 스킬 (`SKILL.md`), 별도 서버/배포 불필요
- **실제 파일**: `sg_ai/.claude/skills/think-first/SKILL.md`
- **버전 규칙**: 1.0 미만은 자기 자신만 쓰는 실험 단계. 소소한 수정은 0.11, 0.12 ...로, 워크플로우가 완전히 달라지면 0.2로 승격
- **배포/공유 (추후)**: 완성도가 올라가면 Git 레포로 배포하고, 본인은 write 권한 유지 + 사용자는 read-only로 clone/pull만 하는 구조로 스킬 업데이트를 동기화. 아직 v0.1 단계라 배포는 하지 않음

## 베네핏 / 리스크

**베네핏**
- 생각하는 힘이 실제로 길러짐 (Why를 직접 실현)
- 대화로 상황이 구체화된 뒤 답을 받아 더 효과적인 답변 확보
- 별도 서비스/회원가입 없이 이미 쓰는 Claude 대화에서 바로 사용 가능
- 평가/점수 없어 사용자 부담이 적음
- 웹서비스 대비 개발/배포 비용이 거의 없어 빠르게 반복 검증 가능

**리스크**
- 생각 유도 마찰이 오히려 이탈로 이어질 수 있음 → 먼저 스스로/지인 대상으로 최우선 검증 필요
- AI의 되묻는 질문이 뻔하면 신뢰 저하
- 스킬을 명시적으로 불러야 하므로 존재를 모르면 아예 안 쓰일 수 있음 → 트리거 문구/온보딩 안내 필요
- 사용자가 계속 짧게만 답하면 되묻기가 끝나지 않을 수 있음 → 5턴 제한으로 대응 중, 실제 동작 검증 필요
- Claude Code 환경에 익숙하지 않은 사용자에게는 진입장벽이 있음 (추후 배포 방식 결정 시 고려)

## 발표 참고 (멘토 피드백)

- 결과물(스킬 데모)보다 Why(왜 이 문제인가)와 What(무엇을 만들었는가)을 먼저 설명할 것
- "이미 만들었습니다"는 짠! 하고 보여주는 순서가 아니라 Why/What 설명 다음 순서여야 함
- 실행은 AI가 대부분 해주므로, 핵심은 Y(문제)를 얼마나 잘 찾고 그걸 해결하는 W(무엇)를 떠올렸는지에 있음을 강조
