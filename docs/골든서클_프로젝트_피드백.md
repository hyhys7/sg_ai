# 골든서클 프로젝트 ("먼저, 생각") 피드백 정리

## 1. 프로젝트 컨셉에 대한 피드백

**문제의식**: 생각이 정리 안 된 상태에서 AI에게 바로 물어보면 원하는 출력값을 못 받는다 → AI가 계속 질문을 던지며 대화로 생각을 정리해주는 도구를 만들고 싶다는 취지.

**멘토 코멘트**:
- 이 방향 자체는 좋지만, 이미 Claude/GPT(Codex)에 유사한 접근이 존재함. 완전히 새로운 프로덕트를 만들기보다 기존 좋은 것 위에 "스킬"을 얹는 방식이 유용성이 더 크다는 지적
- 이 대화형 방식은 안드레이 카파시가 최근 공개한 접근과 유사 — 이미 프론티어 유저들이 다 쓰고 있는 방법이라는 점을 언급하며, 새로 만들기보다 그 방식을 참고/모방할 것을 권함

## 2. 구현 방식에 대한 구체적 제안

- **스킬 파일로 구현**: "네가 나를 완벽하게 이해할 때까지 계속 질문을 주고받는 스킬 파일을 만들어줘"라고 에이전틱 AI에게 요청 → AI가 스킬 파일 설계안을 제안하게 하고, 그걸 리뷰하며 다듬는 방식
- **버전 관리 방식**: 처음엔 1.0이 아니라 0.1부터 시작 (자기 안에서만 쓰는 단계는 1 미만). 소소한 수정은 0.11, 0.12처럼, 완전히 달라지면 0.2로 올리는 넘버링 룰
- 완성 후 다른 사람도 쓸 수 있게 **Git 레포지토리에 배포**하고, 스킬 업데이트될 때마다 동기화(sync/pull)하는 구조를 만들 것을 제안. 본인은 write 권한 없이 read-only로 공유하면 친구/가족/팀원도 최신 스킬을 받아 쓸 수 있음

## 3. 데모(아티팩트) 리뷰 — 구체적 지적사항 ⚠️

- **단순 HTML 카피 방식은 선호하지 않음** → iOS, Android, Google 어디서든 "설치 가능한(installable)" 파일 형태로 바꿔달라고 요청할 것
- **모바일 프렌들리 UI가 아님**: 화면이 랜드스케이프(가로) 기준으로 짜여 있음. 포트레이트(세로)로 보면 글자가 너무 작아서, 특히 50대 중반 같은 사용자층은 보기 힘들다는 지적 — UI 품질을 높일 것

## 4. 발표 준비에 대한 조언

- 결과물부터 보여주지 말고 **Why(왜 이 문제를 다루는가)와 What(무엇을 만들었는가)을 먼저 명확히 설명**할 것 — 슬라이드 한 장, 또는 말로 설명해도 무방
- "이미 만들었습니다"를 짠! 하고 보여주는 건 그 다음 순서여야 함
- 실행(구현)은 이제 AI가 다 해주기 때문에, 핵심은 **Y(문제)를 얼마나 잘 찾고, 그걸 해결하는 W(무엇)를 어떻게 떠올리느냐**에 있다는 점을 강조
